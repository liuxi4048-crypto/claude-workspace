# 納品前チェックリスト

納品は必ずこのチェックリストを通してから行う。**AI が作ったものをノーチェックで納品しない**（品質事故＝低評価は実績づくり期に致命的）。

## 1. 動作確認（人手で必ず実施）

- [ ] 依頼者のサンプルデータ／実ページ相当の条件で、最初から最後まで実際に動かした
- [ ] 正常系だけでなく、想定される異常系を最低2つ試した（空データ、日本語ファイル名、文字コード違い など）
- [ ] GAS の場合: 依頼者の Google アカウント権限で動く構成か（自分の環境依存がないか）
- [ ] スクリプトの場合: 依頼者の OS 環境（Windows/Mac）で動くか。依存ライブラリの導入手順を説明書に書いたか
- [ ] Web 修正の場合: スマホ表示・主要ブラウザで崩れがないか確認した

## 2. 仕様との突き合わせ

- [ ] 着手前に合意した「できること」リストを全項目満たしている
- [ ] 「今回の対象外」に含まれる機能を勝手に追加していない（サービス過剰も往復増加のもと）

## 3. 納品物の体裁

- [ ] 使い方説明書を同梱（スクリーンショット or 手順の箇条書き。専門用語を避ける）
- [ ] コード内の不要なコメント・デバッグ出力・自分のテストデータを削除した
- [ ] 機密情報（API キー・自分のメールアドレス等）が含まれていない

## 4. 納品メッセージ

```
お待たせいたしました。完成しましたので納品いたします。

【納品物】
・{ファイル名}: {1行説明}
・使い方説明書

【動作確認済みの内容】
・{確認した項目を箇条書き — 「確認済み」を明示すると安心感が違う}

まずはお手元でお試しいただき、想定と異なる動きがあればお知らせください。
納品後1週間は無償で調整いたします。

このたびはご依頼ありがとうございました。
```

## 5. クローズ後

- [ ] 取引完了後、work_logs/ に記録（案件概要・金額・かかった実時間・学び）
- [ ] 実際にかかった時間が想定を超えた場合、次回の見積り単価に反映する
- [ ] 評価が3件たまったら価格改定を検討
