# 自律発案ループ（Autonomous Ideation Loop）

**バージョン**: v1.0 | **新設**: 2026-06-16
**目的**: 「AIが自動で発案〜システム完成までを行う」という最上位目的を満たすため、案件・プロダクトの種出しを人間の発語に依存させず、スケジュールで自律的に開始する。

---

## なぜ必要か

これまでの `_index.md` 召喚ルートはすべて「ユーザーがトリガーワードを入力する」「COOがタスクを受け取ってから判断する」という**人間発の入力が起点**だった。
発案そのものを自動化するには、**起点を時間（スケジュール）に置き換える**必要がある。

---

## 自律発案ループの全体フロー

```
[スケジュール起動: 毎日 09:00 JST]
        │
        ▼
   COO 自動起動（人間の「作業開始」発語は不要）
        │
        ▼
   CAIO + CMO を並列召喚 → 市場機会スキャン
   - CAIO: 技術トレンド・AI活用余地の調査
   - CMO: 市場ニーズ・競合動向の調査
        │
        ▼
   提案が1件以上見つかった場合
        │
        ▼
   CEO-Ext ⟷ CEO-Int 自動対立議論（人間の「プロジェクト開始」発語は不要）
        │
        ▼
   Chairman 自動裁定 → decision_log.md 記録
        │
   ┌────┴────┐
  採用        差し戻し/見送り
   │            │
   ▼            ▼
COOが実行計画化   punch_listに理由を記録して終了
   │
   ▼
CPO（要件定義）→ CTO（実装）自動バトンタッチ
   │
   ▼
Internal Tech Auditor 自動監査（スプリント末 or 実装完了時）
   │
   ▼
統合日報に記載 → 必要な場合のみ P0/P1 でユーザーへ報告
```

---

## 人間が関与する唯一のポイント（ゲート）

自動化してもなお人間判断が必須な箇所は、既存の `user_escalation_policy.md` のP0/P1基準に従う。発案ループ特有のゲートは以下の1点のみ。

| ゲート | 条件 | 理由 |
|---|---|---|
| **新規プロジェクトの本格着手** | Chairmanが「採用」と裁定し、かつ予算閾値（¥50,000）または新規技術スタックを含む場合 | `decision_log.md` の既存「召喚基準」に合致するため、P1扱いで当日中にユーザー確認 |

上記に該当しない小規模な改善・検証目的のプロトタイピングは、**ユーザー確認なしでCOOが実行計画化してよい**（P3扱い）。

## スケジュール設定

| トリガー | cron相当 | 起動内容 |
|---|---|---|
| 自律発案ループ | 毎日 09:00 JST | COO起動 → CAIO+CMOスキャン → 提案ゼロなら終了、提案ありならCEO対立議論へ自動連鎖 |
| スプリント末監査 | 2週間ごと | Internal Auditor + Internal Tech Auditor 自動召喚（`_audit_charter.md` 準拠） |
| External Auditor 四半期評価 | Q1/Q2/Q3/Q4末 | `_audit_charter.md` の固定タイミングに準拠し自動召喚 |

実装方法: Claude Code の `/schedule`（scheduled-tasks）機能を使い、上記プロンプトを登録する。COO起動後の召喚・バトンタッチ自体は `parallel_runner.md` のAgent tool運用に従う。

---

## 発案ソースの優先順位

CAIO/CMOがスキャンする際の優先順位。

1. 既存プロダクト（aidesk, kuji-tracker等）のユーザーフィードバック・未実装機能
2. punch_list.md / retro_log.md のTry項目（過去の振り返りからの種）
3. 外部トレンド調査（新規技術・市場ニーズ）

過去ログ起点（1, 2）を優先することで、根拠のない発案を減らす。

---

## 失敗時のフォールバック

- CAIO/CMOが提案を1件も出せなかった日 → 統合日報に「本日は新規提案なし」と記載するのみ。エスカレーション不要（P3）。
- CEO-Ext/Int議論が3回往復しても合意に至らない場合 → Chairmanへ即時エスカレーション（差し戻し前提の裁定を仰ぐ）。
