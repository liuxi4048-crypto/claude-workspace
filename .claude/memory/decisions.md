# 技術的決定の記録

_重要な判断をここに残す。「なぜそうしたか」が後から分かるように。_

---

## 2026-04-30 | baito-kanri: React 19 + Vite を選択

**決定:** バニラ JS や Svelte ではなく React 19 を選択
**理由:** TypeScript サポートの成熟度、Vercel との親和性、将来的な機能追加のしやすさ
**トレードオフ:** バンドルサイズが大きい。PWA 化済みなので初回ロード後は問題なし。

---

## 2026-04-21 | tangocho: Firebase Realtime DB を選択

**決定:** ローカルストレージのみではなく Firebase を採用
**理由:** 複数デバイス間同期（PC・スマホ）が必須要件。Sync ID 方式でアカウント不要を実現。
**トレードオフ:** オフライン時はキャッシュで動作するが、初回はネット接続が必要。

---

## 2026-04-16 | file_rewriter: claude-opus-4-6 を選択

**決定:** Sonnet ではなく Opus をファイル整形 API に使用
**理由:** ファイル整形の品質を最大化。コストより品質優先のユースケース。
**トレードオフ:** API コストが高い。バッチ処理や頻繁な呼び出しには向かない。

---

## 2026-05-08 | CIO エージェント: CLAUDE.md + ファイルベースのメモリを選択

**決定:** 外部 DB や API ではなく、CLAUDE.md + .claude/memory/ のファイルベースで CIO を実装
**理由:** Claude Code が起動時に CLAUDE.md を自動読み込みするため、設定不要で機能する。メモリはテキストファイルなので git 管理も容易。
**トレードオフ:** 自動更新はされないため、重要な決定後に手動 or Claude に依頼して更新が必要。
