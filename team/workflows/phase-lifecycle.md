# フェーズライフサイクル — フェーズ開始・完了手順

---

## フェーズ一覧

| フェーズ | 内容 | ゲート |
|---------|------|--------|
| Phase 0 | 基盤構築（チームフレームワーク・環境） | ユーザー承認必須 |
| Phase 1 | MVP / 核心機能 | 玉城先生承認 + ユーザー承認必須 |
| Phase 2 | 機能拡張 | 玉城先生承認 + ユーザー承認必須 |
| Phase 3 | 品質・最適化 | 玉城先生承認 + ユーザー承認必須 |
| Phase N | プロジェクト確定後に追加 | 同上 |

---

## フェーズ開始シーケンス

```
りつい   → フェーズゴール・スコープ宣言
かなと   → フェーズタスク一覧作成・担当割当
れん     → Linear にフェーズ用マイルストーン + イシュー作成
```

**生成ファイル:** `team/phases/phase-N.md`

## フェーズ内日次サイクル

```
[毎日]
開始トリガー → 作業 → 終了トリガー（日報生成）
```

## フェーズ完了シーケンス

**トリガー:** `フェーズ完了` または全イシュークローズ

### Step 1: 完了基準チェック（けいじ）
```
担当: けいじ
確認: フェーズの完了基準チェックリスト（team/phases/phase-N.md に記載）
出力: 基準達成 / 未達成の判定
```

### Step 2: フェーズ進捗レポート生成（ゆうた）
```
担当: ゆうた
出力: team/reports/phase-N-summary.md
```

### Step 3: 総合審査（玉城先生）
```
担当: 玉城先生
入力: フェーズ全成果物 + 進捗レポート
出力: 承認 / 条件付き承認 / 差し戻し
```

### Step 4: フェーズ完了宣言 + 次フェーズ計画（りつい）
```
担当: りつい
条件: 玉城先生の承認後のみ
出力:
  - フェーズ完了宣言
  - 次フェーズのビジョン・ゴール
  - develop → main マージ要求（ユーザー承認へ）
```

### Step 5: ユーザー承認 ← 必須認証
```
担当: CIO（メインClaude）
アクション:
  - フェーズ完了報告書を提示
  - 玉城先生の審査結果を添付
  - develop → main マージの承認を求める
注意: ユーザーの明示的承認なしにマージ不可
```
