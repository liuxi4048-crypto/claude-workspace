# 終了トリガー — 作業終了・日報生成シーケンス

**トリガー:** `作業終了` / `/project-end`

---

## 実行シーケンス

### Step 1: 進捗収集（ゆうた）

```
担当: ゆうた
操作:
  - 各メンバーの本日作業を収集
  - 完了タスク・進行中タスク・ブロッカーを集計
  - CHANGELOG.md から当日分を抽出
```

### Step 2: 品質チェック結果まとめ（けいじ）

```
担当: けいじ
出力:
  - 本日実施したレビュー件数
  - 指摘事項の件数・種類
  - 差し戻し件数（あれば）
  - 品質上の懸念事項
```

### Step 3: Linear ステータス更新（れん）

```
担当: れん
操作: Linear API でイシューステータスを最新に更新
出力:
  - 本日クローズしたイシュー一覧
  - 翌日持ち越しのイシュー一覧
  - 新規発生したイシュー（あれば）
```

### Step 4: 翌日割当案作成（かなと）

```
担当: かなと
入力: ゆうた の収集結果 + れん のイシュー状況
出力: 翌日のタスク割当案（.claude/memory/task_assignments.md に草案を記録）
```

### Step 5: 本日成果物の総評（玉城先生）

```
担当: 玉城先生
入力: 本日の全実装・レビュー結果・進捗
出力:
  - 当日の総合評価
  - 特に良かった点
  - 改善が必要な点（具体的に）
  - 翌日への注意事項
```

### Step 6: 実装サマリー作成（りゅうき）

```
担当: りゅうき
操作: git log --oneline で本日のコミットを確認
出力:
  - 本日のコミット一覧
  - 完了した実装機能の説明
  - 翌日に引き継ぐ実装状況
```

### Step 7: 日報生成（ゆうた）

```
担当: ゆうた
操作: team/reports/YYYY-MM-DD.md を生成
入力: Step 1〜6 の全情報
出力: 日報ファイル（下記フォーマット）
```

### Step 8: 日報レビュー（りつい）

```
担当: りつい
操作: 生成された日報を確認
出力:
  - 承認 or 修正依頼
  - 翌日への方針コメントを追記
```

### Step 9: ユーザーへの提出 ← 必須認証

```
担当: CIO（メインClaude）
アクション: ユーザーに日報の確認を求める
  - 日報を提示
  - 玉城先生の総評を添付
  - 翌日の割当案を参考提示
注意: この認証は省略不可
```

```markdown

## サマリー
- 完了タスク数: X件
- 進行中タスク数: X件
- ブロッカー: X件
- 品質レビュー: X件実施

## メンバー別作業報告

### りつい（リーダー）
- 承認・決定事項:
- 翌日の方針:

### りゅうき（サブリーダー）
- 実装完了:
- コミット数:
- 翌日引き継ぎ:

### れん（課題管理）
- 作成イシュー:
- クローズイシュー:
- 翌日オープン:

### けいじ（品質管理）
- レビュー件数:
- 指摘事項:
- 差し戻し:

### ゆうた（進捗管理）
- マイルストーン進捗:
- リスク・懸念:

### かなと（人員管理）
- 翌日割当案:

## 玉城先生 総評
（厳格な評価・改善点）

## 翌日の優先タスク
1.
2.
3.

## 変更ログ（本日分）
（CHANGELOG.md から自動抽出）
```

## 出力ファイル

- `team/reports/YYYY-MM-DD.md` — 日報
- `.claude/memory/task_assignments.md` — 翌日割当案（草案）
