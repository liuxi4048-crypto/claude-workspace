# 開始トリガー — 作業開始シーケンス

**トリガー:** `プロジェクト開始` / `作業開始` / `/project-start`

---

## 実行シーケンス

### Step 0: 前日日報の読み取り（ゆうた）
> 初日（日報なし）の場合はスキップ

```
担当: ゆうた
操作: team/reports/ ディレクトリの最新ファイルを Read
出力:
  - 前日の完了タスク一覧
  - 残タスク・未完了事項
  - ブロッカー引き継ぎ
  - 翌日割当案（かなと に連携）
```

### Step 1: 本日方針宣言（りつい）

```
担当: りつい
入力: ゆうた からの前日サマリー（または初日はプロジェクトビジョン）
出力:
  - 本日の優先事項（1〜3項目）
  - 理由と根拠
  - 特別な注意事項
```

### Step 2: タスク分解・割当（かなと）

```
担当: かなと
入力: りつい の方針 + ゆうた の引き継ぎ情報
出力: .claude/memory/task_assignments.md を更新
  形式:
    | メンバー | タスク | Linear ID | 優先度 | 見積 |
```

### Step 3: Linear ステータス確認（れん） — 並列実行可

```
担当: れん
操作: Linear API でオープンイシューを確認
出力:
  - 本日着手予定イシューをステータス更新
  - 新規イシューが必要な場合は作成
```

### Step 4: ブランチ準備（りゅうき） — Step 3 と並列実行可

```
担当: りゅうき
操作: 前日コミットログ確認（git log --oneline -10）
出力:
  - 本日使用するブランチの確認
  - 新規ブランチが必要な場合はりつい に依頼
```

### Step 5: 品質チェック対象確認（けいじ）

```
担当: けいじ
入力: かなと の割当表
出力: 本日レビュー対象の確認・品質チェックリスト準備
```

### Step 6: トラッキング開始（ゆうた）

```
担当: ゆうた
出力: 本日のトラッキング開始宣言 + マイルストーン進捗の現在値を記録
```

### Step 7: 持ち越し審査・本日計画レビュー（玉城先生）

```
担当: 玉城先生
入力: 前日日報・本日計画
出力:
  - 前日成果物の持ち越し問題がある場合は指摘
  - 本日計画の妥当性評価
  - 改善提案（ある場合）
```

### Step 8: ユーザー確認 ← 必須認証

```
担当: CIO（メインClaude）
アクション: ユーザーに本日計画の確認を求める
  - 本日のタスク一覧を提示
  - 玉城先生の評価を添付
  - ユーザーの承認を得てから作業開始
注意: この認証は省略不可
```

---

## 並列実行マップ

```
Step 0 → Step 1 → Step 2 → [Step 3 || Step 4] → Step 5 → Step 6 → Step 7 → Step 8
```

Step 3 と Step 4 は独立しているため並列実行可能。

---

## 出力ファイル

- `.claude/memory/task_assignments.md` — 本日のタスク割当（かなと が更新）
